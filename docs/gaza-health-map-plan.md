# خطة الأسبوع: خريطة الأمراض والرعاية في غزة (Gaza Disease & Care Map)

> **العنوان المعتمد (2026-11-19):** "خريطة الأمراض والرعاية في غزة". المحتوى المتاح فعلاً:
> أمراض معدية بالمحافظة والأسبوع (EWARS 2024–2026)، توفر الخدمات الصحية بالمحافظة (HeRAMS يونيو 2025)،
> سوء التغذية، فجوات الأدوية (لوحة Health Cluster)، وأرقام وطنية للمزمنة والأمهات والنفسية.
> كله بعيداً عن إصابات الحرب. التفاصيل والقيود: `docs/data-sources.md`.
> ملاحظة: الحساسية/الربو بلا مصدر وبائي، والحصبة 16 حالة مشتبهة فقط في 2026؛ نصرّح بذلك على الموقع.

> ملاحظة: هذه المهمة **خارج مراحل CLAUDE.md** (Phase 0–7) وهي مشروع جانبي بموعد نهائي
> خلال أسبوع. تبقى في ملف منفصل ولا تغيّر خطة MedRelay.
> قواعد السلامة في CLAUDE.md تبقى سارية: كل ما يظهر للمستخدم يُكتب عليه
> "بيانات مجمّعة، ليست نصيحة طبية"، ولا نذكر أسماء أدوية كتوصية علاج؛ نعرض فقط
> "احتياجات الأدوية" كما وردت في المصادر.

---

## 1. المطلوب بالضبط (من ملاحظات الاجتماع)

**الهدف:** موقع شغّال خلال أسبوع، ننشره على X و LinkedIn.

**المحتوى:** خريطة للبيانات الطبية في غزة آخر سنتين، على نمط
<https://extranet.who.int/publicemergency/> مع ثلاث طرق للتجميع:

1. حسب **نوع المرض** (disease type)
2. حسب **الموقع** (location)
3. حسب **الأدوية المطلوبة** (treatment/medicine requirements)

**التركيز (تصحيح 2026-11-19):** "الأمراض الطبيعية" = **كل حالة صحية بعيدة عن إصابات الحرب
المباشرة**، وليست المعدية فقط. تشمل: المعدية (حصبة، إسهال، تنفسي، جلدية…)، والحساسية والربو،
والأمراض المزمنة (سكري، ضغط، قلب، كلى، سرطان)، والأمهات والمواليد، وسوء التغذية، والصحة النفسية.
المعدية جزء واحد فقط. (ملاحظة: بياناتنا الحالية قوية للمعدية فقط عبر EWARS؛ باقي الفئات
مصادرها أضعف وتُبحث لاحقاً — انظر docs/data-sources.md.)

**الأسئلة التي يجب أن يجيب عنها العمل:**

- ما هي مجموعات البيانات المتوفرة؟
- ما الاتجاهات (trends) البارزة؟
- توزيع اللغات، والاتجاهات حسب المدن
- الاتجاهات حسب الفئة العمرية، وحسب الجنس

**المشكلة المتوقعة:** معلومات الموقع قد تكون غير موجودة → نحاول استخراجها من
البيانات نفسها (أسماء مرافق، مناطق في نص التقارير، إلخ).

**طريقة العمل المطلوبة:** كل خطوة = مشروع صغير يعمل من البداية للنهاية، ونستعين
بالذكاء الاصطناعي **لكن لازم أقدر أشرح كل شيء**.

---

## 2. خط الأنابيب (Pipeline)

```
جرد المصادر -> تنظيف -> استخراج الاتجاهات/المجموعات -> تخزين (DB) -> خريطة/موقع -> نشر
```

كل مرحلة مشروع صغير له: مدخل، مخرج، اختبار، وسؤال "اشرحه بكلماتك".

---

## 3. المشاريع الصغيرة (Mini-projects) — جدول الأسبوع

### M0 — جرد المصادر (اليوم 1)

**السؤال:** ما هي البيانات المتوفرة فعلاً؟

المصادر المرشحة (من نتيجة البحث؛ كلها تحتاج تحقق من الصيغة والترخيص قبل الاعتماد):

| المصدر | ما قد يحتويه | ملاحظات للتحقق |
|---|---|---|
| WHO EMRO – Emergency Situation Reports | استشارات Health Cluster، مراقبة الأمراض، EMTs | غالباً PDF؛ نحتاج استخراج جداول |
| UN OCHA – Gaza Humanitarian Response Sitreps | أرقام صحية ونقاط وبائية | PDF/HTML |
| HDX – Escalations in Gaza / Health Sector (PCBS) | مؤشرات رقمية | CSV؛ على الأرجح وطنية وليست حسب المدينة |
| Tech for Palestine – Summary Data | وفيات وإصابات يومية | مفيد كسياق فقط؛ ليس أمراضاً طبيعية |
| UNOSAT Gaza Hub | طبقات جغرافية (مرافق، مناطق) | **مهم للإحداثيات** |
| gaza-aid-data.gov.il – Medical response | إمدادات وتنسيق | مصدر طرف مُنسِّق؛ نذكر مصدره بوضوح |

**المخرج:** `docs/data-sources.md` — جدول لكل مصدر: الرابط، الصيغة، الفترة الزمنية،
مستوى التفصيل (وطني/محافظة/مرفق)، هل فيه عمر/جنس/موقع/أدوية؟، الترخيص، قرار
(نستخدم / نتجاهل / سياق فقط). + مجلد `data/raw/` (ملفات خام لا نعدّلها أبداً).

**Done when:** أقدر أجيب عن "ما هي البيانات المتوفرة؟" بجدول، وحمّلت على الأقل
مصدرين بصيغة قابلة للقراءة.

### M1 — التنظيف (اليومان 2–3)

- قراءة الملفات (CSV مباشرة؛ PDF بـ `pdfplumber`/`camelot` أو يدوياً للجداول الصغيرة).
- توحيد: أسماء الأمراض (قاموس مرادفات عربي/إنجليزي)، التواريخ (أسبوع/شهر)، أسماء
  المناطق (غزة، خانيونس، رفح، دير البلح، شمال غزة… بكتابات مختلفة)، فئات العمر،
  الجنس.
- الحقول المجهولة تبقى `null` (لا نخمّن) — نفس مبدأ CLAUDE.md.
- **استخراج الموقع:** (1) من حقل صريح، (2) من اسم المرفق/الملجأ عبر جدول مطابقة
  يدوي مبني على UNOSAT، (3) من نص التقرير. نسجّل لكل صف `location_source`
  (explicit | inferred | unknown) ودرجة الثقة.
- مخرج: `data/clean/observations.csv` بمخطط ثابت (section 4) + سكربت قابل لإعادة
  التشغيل + اختبارات pytest صغيرة (تواريخ، قاموس الأمراض).

**Done when:** تشغيل أمر واحد يعيد بناء `clean/` من `raw/`، ونسبة الصفوف بلا موقع
معروفة ومكتوبة.

### M2 — الاتجاهات والمجموعات (اليوم 4)

يجيب عن أسئلة الاجتماع:

- أعداد الحالات شهرياً حسب المرض (trend)
- حسب المنطقة/المدينة
- حسب الفئة العمرية، وحسب الجنس
- توزيع اللغة: **نفسّر السؤال أولاً** — على الأغلب لغة التقارير/المصادر (عربي/إنجليزي)
  أو لغة الأسماء؛ نؤكد مع المشرف قبل بنائه (سؤال مفتوح Q2 أدناه)
- ربط المرض بـ"احتياجات العلاج": جدول يدوي صغير `disease -> medicine_class`
  (مثلاً: مضادات حيوية، محاليل إماهة، لقاحات) مأخوذ من إرشادات WHO/تقارير
  الإمداد، **مع ذكر المصدر لكل سطر**، لا من ذاكرة النموذج.

**المخرج:** `analysis/trends.ipynb` أو سكربت + 5–8 رسوم + فقرة "ما الذي لاحظته"
بكلماتي. **ملاحظة:** البيانات المجمّعة قد تتأثر بتغيّر طريقة الإبلاغ وانقطاع
المراقبة؛ نكتب ذلك بجانب كل اتجاه.

### M3 — التخزين (اليوم 5)

- SQLite أولاً (الملف مع المشروع، لا يحتاج سيرفر → مناسب لانقطاع الكهرباء)،
  وبنفس المخطط ينتقل لاحقاً إلى Postgres.
- جداول: `sources`, `diseases`, `locations`, `observations`, `medicine_needs`.
- استعلامات جاهزة (views) تقابل التجميعات الثلاثة: حسب المرض / الموقع / الدواء.
- مخرج: `scripts/build_db.py` يبني DB من `data/clean/`.

### M4 — الخريطة والموقع (اليومان 5–6)

- موقع ثابت (static) أبسط ما يمكن للنشر السريع: **Leaflet + GeoJSON + JS عادي**
  (أو Vite). بيانات الخريطة تُصدَّر من DB إلى JSON/GeoJSON جاهز.
- الواجهة: خريطة غزة، فلتر (المرض / الفترة / الفئة العمرية)، تبديل التجميع
  (مرض | موقع | دواء)، رسم زمني صغير، وصف المصدر لكل رقم.
- RTL كامل + ثنائية اللغة (عربي/English).
- تسمية واضحة: "بيانات مجمّعة من مصادر عامة، ليست نصيحة طبية ولا تشخيصاً"،
  وقسم "حدود البيانات" (ما لا تمثّله).
- النشر: GitHub Pages أو Netlify/Cloudflare Pages (مجاني).

### M5 — الإطلاق (اليوم 7)

- README + لقطات شاشة + نص منشور X و LinkedIn.
- قبل النشر: مراجعة كل رقم يظهر مقابل مصدره؛ لا ننشر رقماً لا نعرف مصدره.

## 4. مخطط البيانات المقترح (`observations`)

| الحقل | وصف |
|---|---|
| `id` | معرّف |
| `period_start`, `period_end` | فترة الملاحظة |
| `disease` | اسم موحّد (من القاموس) + `disease_raw` النص الأصلي |
| `cases` | العدد (قد يكون null) |
| `location_name`, `lat`, `lon` | الموقع إن وُجد |
| `location_source` | explicit / inferred / unknown |
| `age_band`, `sex` | null إن غير متوفر |
| `source_id`, `source_page` | تتبّع المصدر (للمراجعة قبل النشر) |
| `notes` | تحفظات |

## 6. المخاطر وكيف نتعامل معها

| الخطر | التعامل |
|---|---|
| البيانات وطنية أو أسبوعية فقط، بلا مدن | نعرض بالمستوى المتاح (محافظة)، ولا نرسم نقاطاً وهمية؛ نكتب "غير متوفر" |
| بيانات PDF صعبة الاستخراج | نبدأ بجداول قليلة يدوياً، ونحوّل لأتمتة فقط بعد نجاح العينة |
| استنتاج الموقع خاطئ | `location_source` + ثقة؛ المستنتَج يظهر بلون/رمز مختلف |
| الأرقام قد تُفهم كتشخيص أو رقم رسمي نهائي | عبارات إخلاء المسؤولية + المصدر والتاريخ بجانب كل رقم |
| تضخّم النطاق في أسبوع | نقص المصادر لا يوقف الموقع: نطلق بما هو متوفر ونكتب القيود |
| استخدام AI دون فهم | لكل مشروع صغير: ملاحظة 5 أسطر "كيف يعمل ولماذا هذا الاختيار" |
